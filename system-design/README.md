# 系统设计题

> 高级岗位的必考环节。考的不是标准答案，而是分析框架和权衡能力。

## 解题方法论

1. **需求澄清**：功能需求 + 非功能需求（QPS、数据量、延迟、一致性要求）
2. **容量估算**：存储量、带宽、QPS 的数量级推算
3. **接口设计**：核心 API 定义
4. **数据模型**：表结构 / 存储选型
5. **核心流程**：画出关键链路，解决核心矛盾
6. **扩展**：容量、可用性、性能怎么横向扩展
7. **权衡**：主动说出方案的 trade-off

## 经典题

| 题目 | 核心矛盾 |
| ---- | -------- |
| 秒杀系统 | 削峰、库存防超卖、防刷 |
| 短链接系统 | 发号器设计、跳转性能、缓存 |
| Feed 流 | 推模式 vs 拉模式 vs 推拉结合 |
| 抢红包 | 随机拆分、并发抢、二阶段提交 |
| 抢票系统 | 超卖、排队、黄牛对抗 |
| 排行榜 | 实时性、Redis zset、分片合并 |
| IM / 评论系统 | 消息顺序、嵌套结构、已读回执 |
| 分布式任务调度 | 分片、幂等、失败重试 |
| 限流器 | 单机 vs 分布式、算法选型 |
| 敏感词过滤 | DFA / AC 自动机、动态更新 |

## 面试高频考点

1. 每道题先答核心矛盾，再给方案，最后说权衡
2. 没有数据量前提的设计都是空谈——主动估算
3. 一致性和可用性出现冲突时如何选择并说出理由
