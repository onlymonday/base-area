# 工程素养

> 区分"能跑"和"能维护"的知识都在这里。与 ai 模块互补：那边是"用 AI 做产品"，这边是"用 AI 提效 + 代码质量本身"。

## 知识地图

### 测试

- 测试金字塔：单元 / 集成 / 端到端的配比与边界
- 单测设计：AAA 结构、测试替身（mock / stub / fake）用到什么程度
- 集成测试与契约测试
- TDD 的适用与不适用场景
- 覆盖率的意义与滥用
- 遗留代码：没有测试的老代码如何安全地补测试、如何解依赖

### 重构与代码设计

- 何时重构：童子军军律、机会式重构 vs 计划式重构
- 常见坏味道与重构手法（提取函数、以多态取代条件等）
- 遗留代码的渐进式改造策略

### Code Review

- Review 清单：正确性、可读性、边界、并发、测试
- 如何提出意见（对人不对事）与如何接受意见

### Git 与协作

- 分支策略：trunk-based vs git flow
- 进阶操作：rebase / cherry-pick / bisect / hook
- commit message 规范

### 文档

- 技术方案设计文档的结构
- 架构决策记录（ADR）

### AI 辅助编程

- AI 编程工具（Copilot / Claude Code 类）的高效用法
- AI 生成代码的质量把关：测试兜底、Review 要点
- 什么时候不该用 AI 生成

## 面试高频考点

1. 没有测试的老代码怎么安全地改？
2. 单测应该 mock 到什么程度？mock 一切有什么问题？
3. rebase 和 merge 怎么选？
4. 怎么保证 AI 生成的代码质量？
5. 一份好的技术方案文档应该包含什么？
