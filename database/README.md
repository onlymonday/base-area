# 数据库

> 后端面试的重中之重。围绕 MySQL 与 Redis 展开，兼顾 MongoDB 与分库分表。

## 知识地图

### MySQL

- 索引：B+ 树原理、联合索引与最左前缀、覆盖索引、索引失效场景、索引下推
- 事务：ACID 实现、隔离级别与脏读/幻读、MVCC 原理（ReadView + undo log）
- 锁：全局锁/表锁/行锁、间隙锁与临键锁、死锁排查
- 日志：redo log、undo log、binlog 的作用与区别、两阶段提交
- 主从复制、读写分离、主从延迟
- SQL 优化：执行计划（explain）、慢查询定位

### Redis

- 数据类型与底层编码（SDS、跳表、压缩列表等）
- 持久化：RDB / AOF / 混合持久化
- 高可用：主从、哨兵、Cluster 集群
- 缓存问题：穿透、击穿、雪崩、缓存与数据库一致性
- 分布式锁（setnx、Redisson、RedLock）
- 过期删除策略与内存淘汰策略

### MongoDB

- 文档模型与适用场景
- 副本集与分片集群
- 索引与聚合管道

### 分库分表

- 垂直拆分与水平拆分
- 路由策略与扩容迁移
- 跨库查询、跨库事务、全局 ID

## 面试高频考点

1. 为什么 MySQL 用 B+ 树而不是 B 树 / 哈希 / LSM 树？
2. 讲讲 MVCC 的实现原理
3. binlog 和 redo log 有什么区别？两阶段提交解决什么问题？
4. 缓存与数据库一致性怎么保证？
5. Redis 为什么快？单线程为什么还这么强？
6. 缓存穿透、击穿、雪崩分别怎么解决？
7. 分库分表之后，分页查询和跨库 join 怎么办？
